# Feedback：执行复盘与改进建议

用户要求回顾一段时间的团队执行、查慢任务、重复劳动、职责交叉或生成改进报告时读取。
这是 Skill 的工作入口，不是 `herdr-team feedback` CLI 命令；不新增调度器、遥测或后台轮询。

## 执行顺序

1. 先收集执行证据、分析并保存完整本地报告；上游候选问题与 issue 草稿也先写在报告中。
   此阶段不查询 GitHub issue、不检查 GitHub 登录或插件更新；不因缺少 gh 认证而改用 curl 或其他 API 查询。
   复盘所需的任务 PR/CI 证据仍可按需读取，但不借此提前搜索工具仓库的 issue。
2. 把报告交给用户查看，确认哪些发现属于 Herdr / herdr-team 插件问题、是否需要向上游提交。
   仅要求报告时到此完成；先前已有发布授权也不能跳过本地报告与问题确认。
3. 只有报告完成、上游问题已确认且用户决定提交后，才核对目标仓库、查询相似 issue，决定复用或新建，再发布。

## 范围与证据

用户可说“使用 herdr-team skill 的 feedback，复盘最近 7 天”，也可指定日期、任务或关注点。
未指定时间时使用最近 7 天，记录实际起止时间、时区、项目绝对 root 和分析时刻；用户已指定的范围优先。
同项目可以有多个 workspace。以具体 pane/tab/workspace 绑定、任务和 delivery 关联记录，不按目录名全局猜会话。

1. 读取项目 AGENTS.md、根 TEAM.md、角色说明和已有反馈报告，理解实际约定及之前建议的处理情况。
2. 用只读 `herdr-team tasks --json --root <team-root>` 获取索引，再读候选卡的 `.task.yaml`、task.md 历史与交付摘要。
   纳入时间窗内有执行事件或与时间窗重叠的任务，包含进行中、blocked、cancelled 和窗口前开始的任务。
   不能只看当前 doing/done，也不能把列表中的当前角色或已缩短的 handoff 当成原始执行链。
3. 按需核对引用报告、测试日志、Git commit/变更路径、PR 与 CI 记录。只为候选异常补读相关证据，
   不为复盘重跑测试、启动 agent 或遍历全部 harness 对话。Herdr 实时状态只能证明当前状态，不能还原历史。
   需要实时 pane 信息时使用 Herdr skill；离线或缺记录时继续生成有边界的报告。
4. 文件 mtime 只帮助筛选，不作为建卡、开始或完成时间。先判断数据覆盖率；缺少历史、被清理的日志和
   无法定位的会话列为缺口，不能凭任务 ID 大小或相似标题补时间。历史正文以实际记录为准，不按固定措辞解析。

任务时间来自实际字段与事件：当前 delivery 有 queued_at、可选 sent_at；已完成 delivery 主要留下 ID 和 Markdown 历史。
不要假定存在 created_at、claimed_at 或每阶段 completed_at。ISO 时间带时区；无时区的历史时间须注明解释依据，
不同机器的时区或时钟不明时不精算跨机器间隔。提交时间证明版本存在，不证明 agent 正在工作。

## 主动分析

| 方向 | 要找什么 | 判定边界 |
| --- | --- | --- |
| 耗时 | 周转时间较长的任务、等待投递/验收/合并、反复返工、长期受阻 | 分阶段列可观测起止与证据；区分等待和阶段墙钟时间。没有活动追踪就不能称为纯执行/模型耗时 |
| 重复 | 同一目标重复建卡、同 SHA 同范围的重复检查、重复研究/修复、uncertain 后盲目重派 | 按任务、delivery、operation marker 和 SHA 去重；换 SHA 的重测、按约定独立验收、幂等回执不算浪费 |
| 交叉 | 不同任务同时修改相同文件/接口、角色职责互相覆盖、共用数据库/Redis/端口、同 checkout 并行写入 | 同文件/接口重叠先标交叉风险；确认干扰需同 checkout 并发写入、资源冲突或不兼容改动的证据。同仓库、相似标题、多 workspace 和正常逐棒共用 checkout 不等于冲突 |
| 流程与环境 | 无必要依赖、lead 中转、重复审批、职责缺口、集成过旧、登录/工具/隔离配置缺失、收尾遗漏 | 对照当时约定和实际错误，不把手动等待直接归咎于角色或模型，也不把定制配置错误直接算作上游缺陷 |

先展示少量最影响交付的任务与模式，用可观测耗时、重复次数、受影响任务和返工证据排序，不制造固定超时阈值。
只比较规模和验收范围相近的任务；样本少时列个案，不给角色打效率排名。
进行中任务列当前已观察时长，不能当作完成耗时参与均值；窗口内时间和完整任务周转分别注明。
并行阶段的墙钟时间不能直接相加当作总耗时。历史交棒或合并事件无时间时标未知/区间，不输出伪精确数字。

每条发现给出：任务/delivery/SHA 与来源位置、观察事实、原因假设及置信度、影响、最小改法、负责人和验证方式。
重复模式可合成一条发现并附受影响任务；同一原因的本地缓解与上游修复关联同一发现，不重复统计收益。
证据必须能定位并支持具体结论：给任务号、delivery/SHA、文件路径与行号或事件时间，附关键原文或变更摘要，
说明它如何证明问题。仅列报告路径、日志数量或“测试已通过”不能证明验收遗漏、职责冲突或返工原因。
“退回 N 次”等统计要附口径、去重后的事件清单及来源；区分退回次数、受影响任务数和已证实原因，
不能仅凭退回措辞断言“仅因文档冲突”。证据不足的原因标为推测或待核实，并说明还缺什么。
建议要落到具体角色、文件/配置或验收动作，说明改什么、由谁负责、如何验证；避免只说“加强协作/完善测试”。

## 两类改进出口

### 上游：Herdr / herdr-team Skill 的 GitHub issue

可复用到其他项目的 Skill 指引、模板、交付协议、CLI 或 Herdr 集成缺陷归上游；项目自定义角色或环境问题先归本地。
报告阶段依据本地安装来源、仓库文档或包元数据标注候选负责仓库，不把当前业务 repo 的 origin 当成工具 issue 目标。
Herdr Team 的本技能与 CLI 问题提交到 `boyd4y/herdr-team`；原生 Herdr 问题应核对其实际维护仓库。
证据不足时保留为待核实建议；不要为了凑反馈给所有异常开 issue。

报告附 issue 草稿：标题、版本/平台、预期与实际、最小复现或历史证据、影响范围、建议改法和验证条件。
对外使用可公开的最小示例，移除凭证、业务数据、客户信息、私人路径与无关会话内容；私有报告路径不能当作维护者可访问的证据。

完成本地报告、确认上游问题并获用户提交决定后，查该仓库已有 open/closed issue 和先前报告的 issue 链接；
已有同类问题就复用，新增证据的评论也遵循发布授权。认证不可用时保留报告和草稿，说明发布受阻，
不要为完成复盘启动登录流程或反复切换查询方式。
确认目标后用 `gh issue create --repo OWNER/REPO --title TITLE --body-file FILE` 发布，并把返回 URL 回填报告。
结果不明先查远端，不重复提交；未发布须明确标为草稿。不要把用户业务任务发送到上游 issue。

### 本地：当前仓库改进

针对责任边界、workflow、角色 prompt、项目文档、测试范围、依赖拆分和工具/环境配置提出具体改法。
每项写明目标文件或配置位置、负责角色、优先级、最小修改、预期效果和验证条件。
角色步骤调整见 [setup.md](setup.md)，协作与交付改进见 [handoff.md](handoff.md)；不把操作流程复制进 TEAM.md 或 role prompt。

feedback 默认只诊断和建议；用户要求落地修复或已有对应实施授权时，再按正常任务链执行，
保留活动任务当前指派及历史，不为复盘自动取消、重派、改卡或重写已有 workflow/角色正文。
涉及缺失凭证、用户账号或实际环境选择时指出所缺输入，不凭猜测换库、占端口或改变生产配置。

## 报告与后续

按 [报告模板](../assets/feedback/report.md) 输出到主检出的 `.herdr/reports/feedback/<时间范围>-<生成时间>/report.md`。
这是本地报告，`.herdr/` 整体忽略；保留旧报告，不放在将要回收的 worktree。
无异常也报告覆盖范围与缺口，不编造发现；无任务时说明无法得出效率结论，不要求用户编造试运行任务。
已有反馈按稳定发现 ID 或关联任务/issue 对照改进效果，未落实建议仍可保留，但不重复建 issue 或修复卡。

### 对话回复

回复先直接回答核心问题：最影响交付的瓶颈是什么、证据支持到什么程度、优先改什么。
优先展示最重要的几条，每条把“问题 → 证据 → 具体建议”放在一起：

- 问题与影响：明确事实，原因推测单独标注。
- 证据：任务号、可点击的来源文件/行号或 commit/PR 链接，附关键事件或原文；汇总数量同时链接统计明细。
- 建议：最小修改、负责角色、目标文件/操作与验证条件；明确属于仓库改进还是上游候选。

用户应能在对话中判断结论及下一步，不必打开报告才知道证据和建议。报告链接用于查阅完整明细，
不能用“建议已写入报告”代替具体建议，也不能只给无证据的发现清单。
最后附报告路径、关键证据缺口和建议状态；只报本地读取到的版本，不在复盘中声称“已确认最新”。
