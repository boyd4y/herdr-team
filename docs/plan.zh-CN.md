# 实施顺序

## 1. 原生预览与边界确认（本次）

- 新建独立 Git 仓库、`team` layout、`team-console` mod 和显式 Sample。
- 用现有 CLI JSON 读取任务和角色；Core 状态只读，不开始执行业务任务。
- 核对原生加载、任务倒序、机器/space 隔离，以及同角色并行任务互不借用状态。

交付标准：本机原生 check 与行为测试通过；说明尚未做完整窗口验收。

## 2. 打通一个真实任务

- 为既有 CLI 定义最小运行接口：启动、检查就绪、发送、观察、恢复、停止。
- Core adapter 使用结构化参数；桌面版布局命令负责呈现终端。实例保存 project、machine、space、terminal、role、task 的确切绑定。
- 区分协调 space 与任务 worktree space，用 `team.owner_space` 明确归属；同项目另开的团队实例不能因为路径相同而抢用任务终端。
- 在隔离项目完成：启动 dev → 收到 delivery → claim → 提交结果 → handoff 给 test。任务同一 worktree 顺序推进，不在第一版增加 dev/test 混合并行。
- 验证 Codex 无 daemon，agent 状态确实由协议上报；不借用旧版 Herdr 的 session 或 metadata。

交付标准：真实任务可接收并交棒；启动失败、未知提交和重启不会产生第二份任务或额外 workspace。

## 3. 队列、恢复与最终收尾

- 明确 Core 托管 coordinator 的启动、单实例租约、事件订阅与停止方式。窗口关闭后是否继续派活要有明确行为。
- 保留既有 delivery 幂等和锁；测试 agent 忙、审批阻塞、用户草稿、超时、断线、事件 missed。
- 原生对话恢复保存实际可用的 session；程序丢失后的 shell 不算恢复成功。
- 最后一棒在必要合并成功后显式清理任务实例与 worktree；保留常驻角色和其他任务。

交付标准：两个独立任务可并行，单任务交接有序；重复投递、交叉项目、误关闭和错误合并的测试通过。

## 4. 打包和扩展

- 接通 ACP/ACPC 的 OSC 7501 状态桥，核对 `acp(remote)`、模型选择和恢复；保留成熟客户端的 TUI。
- 增加实际需要的团队操作入口，不复制 CLI 命令目录或 workflow 管理器。
- 完成文件监听故障、远程机器、不同窗口尺寸、多个同项目 space 和长标题验收。
- 提供仅管理本插件文件的安装/更新/卸载，保留个人修改；增加真实截图后再发布 layout/mod。

交付标准：用户可从文档安装和更新；能力声明对应真实证据，不能把当前样例视为完成迁移。
